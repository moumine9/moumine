The problem is a graph, so the internal model is a graph. Tickets are *nodes*; parent/subtask/link/mention are *typed edges*; merge requests and commits attach as satellite nodes hanging off the ticket they resolve. Once shaped this way the "walk from a single Jira key" step is a graph traversal, not a bespoke stitching algorithm.

Backing this design with Neo4j — modeling the same shape in a real property graph and driving it with `Cypher` — is what the recent GraphAcademy work (`Neo4j Fundamentals`, `Cypher Fundamentals`, `Graph Data Modeling Fundamentals`, `Intermediate Cypher Queries`, plus the two `Importing Data` courses) fed directly back into. The in-memory graph latoile ships today is the same shape you would persist to Neo4j the moment traversal cost, not fetch cost, becomes the bottleneck.
